# V4 需求基线：多用户、邮件简报与追踪内容

> 状态：已确认（2026-09-07）
>
> 基线：V3 已完成并部署
>
> 关联 Issue：#28-#33

## 0. 已确认决策摘要

- V4 独立于 V3，作为新的迭代基线；不修改 V3 已确认需求、验收和部署成果。
- 实现真正的多用户数据隔离；现有 `default` 数据迁移到第一次初始化的用户。
- 不开放注册；登录页支持用户名或邮箱 + 密码，服务端使用 HttpOnly 安全会话。
- 用户管理仅通过终端命令完成：新增、列出、重置密码、启用/停用。
- 每个用户拥有时区、地区、日报/邮件简报时间和通知渠道配置。
- 支持通用 IMAP 邮箱账户；密码/授权码使用服务端密钥加密存储。
- 邮件系统首次同步最近 7 天，后续按 IMAP UID 增量同步；邮件正文保留 60 天。
- 邮件简报与日报完全分离；推送只通知“邮件简报已生成，请前往网页端登录查看”，不推送正文。
- 排除规则优先，LLM 辅助判断；LLM 对邮件输出 1–10 重要度分数并给出原因。
- 追踪内容支持从邮件一键生成或手动新增，权重 1–10；最终分数为 `min(10, 原始分 + round(追踪权重 × 匹配度))`。
- 邮件简报每用户独立生成，默认 Top 20 可配置；支持手动触发和历史查看。
- 邮件账户、追踪内容、邮件简报、个人设置均为网页可管理；用户可给自己的通知渠道做测试。
- 新增 `argon2-cffi` 与 `cryptography` 依赖，密码使用 Argon2id，邮件凭据使用 Fernet 加密。
- V4 通过 6 个带依赖关系的主 Issue 推进，使用 `V4` 标签和功能前缀。

## 1. 背景与目标

V3 已经完成单用户的联网日报问答。当前数据库虽然为部分表预留了 `user_id`，但没有用户表、登录页或真正的用户隔离；日报快照、内容条目和聊天记录仍缺少 `user_id`。

V4 的目标是把助手从“单用户工具”升级为可由管理员创建账户的“个人信息平台”，并在不影响日报链路的前提下新增邮件简报和追踪能力：

1. 管理员通过终端命令创建首个和后续用户，用户通过网页登录。
2. 每个用户看到自己的日报、收藏、设置、邮件账户、追踪内容和邮件简报。
3. 每天按用户配置的时间拉取过去 24 小时邮件，过滤促销后按重要度排序生成简报。
4. 用户可以用追踪内容提高相关邮件的重要度，并在网页管理所有邮件相关内容。

## 2. 范围与边界

### 范围内

- 用户表、登录会话、密码哈希和密码重置。
- `user add/list/reset-password/enable/disable` 终端命令。
- 首次用户初始化和 `default` 历史数据迁移。
- 每用户的日报与邮件简报调度。
- IMAP 邮件账户、连接测试、增量同步和邮件存储。
- 排除规则、LLM 重要度评分、邮件简报生成和追踪提升。
- 登录页、个人设置、邮件账户、追踪内容、邮件简报页面。
- 每用户通知渠道与“已生成”通知。
- V4 验收、ADR、迁移指引和 Issue 跟踪。

### 范围外

- 用户自助注册、找回密码、修改密码的网页流程；密码管理仅通过 CLI。
- 企业微信智能机器人 userid 与内部用户映射；V4 智能机器人继续服务默认用户。
- 邮件发送；V4 只接收和读取邮件。
- 同步完整收件箱历史、搜索全文邮件或长期邮件归档。
- 附件、图片、HTML 渲染和邮件中的二进制内容。
- 多用户权限层级、角色或管理员 UI。
- 邮件简报内容通过推送渠道发送；通知只提示网页查看。

## 3. 详细需求

### V4-01 用户与鉴权

- 新表 `users` 保存 `id`、`username`、`email`、`password_hash`、`is_active`、`created_at`、`updated_at`。
- `username` 与 `email` 在用户维度唯一，登录时先按 username 再按 email 查找。
- 密码使用 Argon2id 哈希；登录失败做统一模糊提示与频率限制。
- 登录成功后签发 HttpOnly 会话 Cookie，`SameSite=Lax`，生产环境 `Secure`；默认 30 天滑动续期。
- 提供 `POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`。
- 所有用户数据 API 必须从当前会话解析 `user_id`，禁止用全局 `default` 代替。
- 保留可关闭的旧全局 token 兼容层，完成 V4 验证后由部署决定是否移除。

### V4-02 用户设置与调度

- 每用户设置包括：`timezone`、`location`、`daily_report_time`、`mail_digest_time`、通知渠道、`is_active`。
- 网页“个人设置”页允许用户编辑自己的时区、地区、时间、通知渠道和启用开关；密码不在此页面修改。
- 调度器遍历启用用户，分别执行日报生成、邮件同步和邮件简报生成；任一用户失败不能阻断其他用户。
- 定时任务记录每用户运行状态、错误与降级信息。

### V4-03 邮件账户与同步

- 邮件账户字段：显示名、IMAP 主机、端口、SSL/TLS、邮箱地址、登录账号、密码/授权码、可选收件箱、状态。
- 保存前必须测试连接；失败时不保存或明确标记，测试过程不留下完整密码日志。
- 邮件凭据使用 `ENCRYPTION_KEY` 加密后再写入数据库；任何 API 不回传明文。
- 首次同步最近 7 天，之后记录 UID 并增量同步；同一邮件按 Message-ID 跨账户去重。
- 邮件正文保存为纯文本，不保存附件、图片、HTML；正文与元数据保留 60 天。
- 删除账户默认软删除：停止同步但保留历史；永久清除需二次确认并写审计记录。

### V4-04 排除、评分与简报

- 排除规则按用户保存，字段包括：名称、匹配字段、匹配方式、模式、动作、优先级、启用状态。
- 内置促销邮件启发式：常见域名/发件人、主题垃圾词、退订头、列表头等。
- 规则未排除的邮件进入 LLM 评分；每封输出 1–10 分、简短原因和主题类别。
- 单次简报最多评分 200 封邮件；评分失败重试 1 次，仍失败则以默认 5 分进入并标记降级。
- 简报默认保留 Top 20，可配置；同主题可合并，保留邮件 ID、发件人、时间、摘要和原邮件链接。
- 简报快照、运行记录和通知记录保留 180 天。

### V4-05 追踪内容

- 支持从邮件简报中的邮件一键创建追踪内容，支持手动新增、编辑、删除。
- 追踪内容包含：名称、正文/关键词/描述、来源邮件 ID（可选）、权重、启用状态。
- 权重范围 1–10，默认 5；匹配度 0–1，默认阈值 0.6。
- 先做标题和正文关键词硬匹配；未命中或模糊时使用 LLM 语义匹配。
- 命中结果在简报页标记“因追踪提升”，并展示提升前后的分数。

### V4-06 网页与通知

- 页面：登录页、个人设置、邮件账户、追踪内容、邮件简报。
- 登录后前端所有请求携带会话 Cookie；不把会话或 token 写入 localStorage。
- 邮件账户页支持新增、编辑、软删除、永久清除、测试连接；编辑时密码留空表示不修改。
- 追踪内容页支持新增、编辑、删除、权重和启用状态。
- 邮件简报页支持日期切换、查看原邮件、追踪该邮件和“立即生成”。
- 通知内容固定为“您的邮件简报已生成，请前往网页端登录查看”，附登录链接；提醒内容不包含邮件正文。

### V4-07 安全与保留

- 新增依赖：`argon2-cffi`、`cryptography`。
- `.env` 新增 `SECRET_KEY` 与 `ENCRYPTION_KEY`；权限 600，缺失或长度不足时拒绝启动相关功能。
- 邮件正文加密存储；日志、错误页和 API 响应中不得出现密码、授权码或完整邮件正文。
- 数据保留：邮件正文 60 天；邮件简报/运行通知 180 天；追踪与排除规则长期保留。

### V4-08 迁移与交付

- 数据库迁移自动备份 SQLite、幂等创建新表和补充 `user_id` 列。
- 提供 `user bootstrap` 初始化第一个用户并迁移 `default` 数据。
- 迁移前校验两个服务端密钥；密钥缺失时拒绝执行。
- 交付物：`docs/v4-requirements.md`、`docs/v4-acceptance.md`、`docs/v4-migration-guide.md`、ADR-0006、6 个 V4 Issue。

## 5. 人工迁移事项

具体操作见 `docs/v4-migration-guide.md`。原则上数据库表结构、`default` 数据迁移、默认值补齐均由 CLI 完成；用户只需要执行备份、保存密钥、运行初始化命令、登录配置邮箱和验证简报。
