# 联网问答使用 DeepSeek Responses API 原生搜索与受控网页读取

- 状态：已接受
- 日期：2026-09-02

V3 需要让日报助手在用户主动问答中访问网页并自行搜索，同时保持 V2 日报生成与快照语义不变。决定在问答链路使用 DeepSeek 官方 Responses API 的服务端 `web_search` 与 `web_search_2025_08_26`，并通过独立适配器支持后续替换；网页正文读取由项目自建的受控 HTTP(S) 提取器完成。日报摘要等非问答调用继续使用现有 Chat Completions，避免搜索能力改变日报生成行为。

选择 DeepSeek 原生搜索而非第三方搜索 API，是因为当前项目已使用 DeepSeek，复用同一账号可以减少密钥和供应商依赖；原生服务端搜索也能返回可引用的来源信息。选择自建受控网页读取而非浏览器自动化，是因为 V3 只需读取普通 HTML、Markdown 和纯文本内容，浏览器自动化会带来明显更重的部署、资源和兼容性成本。

## 影响

- 问答调用需从 Chat Completions 迁移到 Responses API，搜索工具、流式事件和来源引用需要单独适配。
- 服务端搜索的区域、结果数量和部分行为由供应商控制；搜索质量、成本和来源结构需在开发前用真实样本验证。
- URL 读取必须承担公网页面格式差异、SSRF 防护、内容大小限制、缓存和失败降级。
- 本机开发可直接访问外网；服务器若无法访问外部站点，可通过可选代理配置解决。
