# V3 需求基线：日报助手联网问答

> 状态：已确认（2026-09-02）
>
> 基线：V2 已完成能力
>
> 关联 Issue：#25

## 0. 已确认决策摘要

- V3 只在用户主动问答中启用联网能力，不改变每日 08:00 自动日报生成、保存和推送链路。
- 网页端与企业微信智能机器人共用同一套联网问答服务。
- 搜索采用 DeepSeek 官方 Responses API 的服务端 `web_search`；现有日报摘要仍使用 Chat Completions，不复用联网问答入口。
- 支持受控的公网 HTTP(S) 网页读取；默认禁止内网、localhost、非 HTTP(S) 协议及 SSRF 重定向。
- 联网时机采用“自动判断为主、用户强制为辅”：全局默认开启，网页端提供会话开关，企业微信支持自然语言指令。
- 回答必须带来源标题和 URL；无法确认的信息必须明确说明，不得编造来源。
- 搜索默认中文优先、国际英文源补充，并将当前配置地区注入查询上下文。
- 优先官方和权威来源，不设硬性业务白名单；支持可配置黑名单。
- 单次联网问答最多 2 次搜索、3 个网页读取；网页端最长 60 秒，企业微信最长 90 秒。
- 每日联网问答默认上限 100 次；达到上限后降级为离线回答并提示用户。
- 网页端流式输出，企业微信第一版非流式。
- 搜索不缓存；网页正文缓存 10 分钟，同一会话中相同 URL 不重复读取。
- 会话沿用 7 天、最多 50 条；单次问答使用最近 10 条消息、当前日报/本地信息和本次搜索结果。
- 只保存搜索查询、命中 URL 与引用元数据，不保存网页全文。
- V3 验收需覆盖网页端和企业微信端，完成端到端人工验证后才关闭主 Issue。

## 1. 背景与目标

V2 已完成日报生成、网页端日报问答、企业微信智能机器人问答、极端天气预警、收藏和数据可视化。当前问答只基于日报快照与本地信息，没有访问外部网页和实时搜索的能力。

V3 的目标是在不改变日报快照语义的前提下，把“日报助手”的问答从静态上下文升级为可联网查证的问答：用户询问最新或实时事实时，助手可以搜索外部信息并读取公网页面，同时保留可追溯来源和离线降级能力。

## 2. 范围与边界

### 范围内

- 网页端日报问答联网能力。
- 企业微信智能机器人联网问答能力。
- 面向当前日报、天气、预警、收藏等本地信息的查询增强。
- 服务端 `web_search` 与受控 HTTP(S) 网页读取。
- 联网状态、来源引用、用户开关、失败降级、缓存和限额。
- V3 需求文档、V3 验收清单、ADR-0005、V3 主 Issue。

### 范围外

- 自动日报生成阶段联网搜索或改写日报内容。
- 历史日报日期检索。
- 通用聊天助手定位：不做任意领域开放式助手，仅在现有“日报助手”问答语义内补充外部实时事实。
- PDF、图片 OCR、视频字幕等媒体内容解析。
- 访问需要登录、校验或非公网的内网页面。
- 多用户账号与权限体系。
- 长期记忆、多 Agent 编排。

## 3. 详细需求

### V3-01 联网问答入口

网页端 `POST /api/chat` 与企业微信智能机器人的 @ 提问复用同一问答服务。入口能力包括：

- 自动判断是否需要联网：先检查日报与本地已有信息，仅在涉及最新、实时、外部事实或用户明确要求搜索时发起联网。
- 用户控制：全局配置默认开启；网页端提供会话级联网开关；企业微信支持“联网/搜索/查一下”和“不联网/离线/不搜索”指令。
- 上下文：最新日报、当前天气/预警、收藏等本地信息 + 本次搜索/网页读取结果。
- 状态：网页端显示“正在联网检索/读取页面/正在回答”；企业微信回复开头标记“已联网检索”。

### V3-02 搜索能力

- 使用 DeepSeek 官方 Responses API 的 `web_search`/`web_search_2025_08_26`，在问答链路中启用服务端搜索。
- 问答 LLM 调用迁移到 Responses API；日报摘要、问答之外的其他 LLM 调用保持现有 Chat Completions 行为。
- 默认模型为 `deepseek-v4-flash`，支持配置切换 `deepseek-v4-pro`。
- 搜索查询默认中文优先、国际英文源补充；将配置地区注入提示词，弥补服务端 `user_location` 被忽略的限制。
- 单次最多 2 次搜索；每次外部请求 10 秒超时；临时失败最多重试 1 次。
- 搜索结果必须用于回答并形成来源引用；不得仅凭未核实的搜索摘要直接编造事实。

### V3-03 受控网页读取

- 支持用户提供 URL，也允许模型自动读取搜索结果中的相关页面，单次最多 3 个页面。
- 仅接受公网 `http(s)` URL；默认拒绝 localhost、私有/环回 IP、内网地址、非 HTTP(S) 协议和重定向到受限地址。
- 支持普通 HTML、Markdown、纯文本页面；V3 不处理 PDF、图片、视频。
- 正文大小、响应时间、重定向和内容类型需受控；读取失败计入联网失败降级流程。
- 同一会话中相同 URL 短期不重复读取；网页正文缓存 10 分钟，缓存不保存完整原始页面。

### V3-04 可靠性、降级与限额

- 网页端总响应上限 60 秒，企业微信总响应上限 90 秒。
- 搜索/读取失败重试 1 次；仍失败时降级为本地日报与模型已有知识作答，并明确提示“联网检索失败/部分信息无法确认”。
- 每日联网问答上限默认 100 次；达到上限后不再发起外部搜索，降级为离线回答并提示。
- 单次联网问答的过程应记录为可诊断的元数据，但不得保存网页全文。
- 会话保留策略沿用 7 天、最多 50 条；构建上下文时最多带入最近 10 条消息。

### V3-05 来源与展示

- 回答必须附来源标题和 URL；网页端提供可展开的来源卡片，企业微信末尾最多列 3 条来源链接。
- 优先官方和权威来源；业务黑名单默认空，可通过配置添加。
- 找不到可靠来源时，回答必须说明无法确认，不生成“看起来合理”的引用。
- 网页端流式输出，企业微信第一版非流式；企业微信回复需要保留来源链接，不应因截断导致链接不可用。

### V3-06 安全

- URL 读取必须实施 SSRF 防护：校验协议、解析域名、阻断私有网段、处理 DNS 重绑定风险、限制重定向目标。
- 外部请求不携带本地凭证；不得读取 `file://`、内网服务或带认证的私有页面。
- 黑名单配置只记录域名/主机名，不存储 API Key、Cookie 或其他敏感信息。
- 本机开发不使用代理；服务器如需要代理，通过可选的 HTTP(S) 代理配置提供，默认关闭。

### V3-07 配置

新增/扩展配置至少包括：

- `web_search_enabled`：全局联网开关，默认开启。
- `web_search_model`：联网问答模型，默认 `deepseek-v4-flash`，可切 `deepseek-v4-pro`。
- `web_search_max_rounds`：单次搜索上限，默认 2。
- `web_page_max_reads`：单次网页读取上限，默认 3。
- `web_fetch_timeout_seconds`：单次外部请求超时，默认 10。
- `web_page_cache_ttl_seconds`：网页正文缓存 TTL，默认 600。
- `web_daily_limit`：每日联网问答上限，默认 100。
- `web_blocked_hosts`：业务黑名单，默认空。
- 可选 `http_proxy`/`https_proxy`：服务器代理配置，默认空。

## 4. 架构与实现约束

- 新增 `WebSearchAdapter` 或等价抽象，搜索服务可替换；默认适配 DeepSeek Responses API。
- 新增受控 URL 读取模块，负责 URL 校验、HTTP 请求、正文提取、大小限制、缓存和安全日志。
- 问答服务在调用前构建“本地上下文 + 搜索结果 + 网页正文”的引用集合；LLM 只使用该集合中的事实。
- 现有 `answer_question` 的本地问答行为不得被破坏；联网失败后必须回退到原路径。
- 所有外部网络请求必须通过现有测试隔离方式模拟，不在单元测试中访问真实网络。

## 5. 风险

1. DeepSeek 服务端 `web_search` 的搜索细节和结果结构由供应商控制，可能无法完全自定义区域、结果数量和来源排序。
2. 公网页面结构和内容质量差异大，正文提取可能失败或产生噪音，需要采样验证。
3. 企业微信回复长度、非流式交互和群聊频率限制可能影响来源列表和用户体验。
4. 联网成本未被官方单独明示，V3 上线前应通过真实小样本验证并观察每日用量。
5. 服务器若需代理，网络配置和失败降级需要额外验证。
